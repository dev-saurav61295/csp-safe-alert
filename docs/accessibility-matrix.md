# Accessibility Matrix: WCAG 2.2 Level A/AA Assessment

This matrix assesses all applicable WCAG 2.2 Level A and AA criteria for `csp-safe-alert`.

| WCAG SC | Principle & Criterion | Level | Applicability | Component Implementation & Responsibility | Host Responsibility | Verification Method | Status |
|---|---|---|---|---|---|---|---|
| **1.1.1** | Non-text Content | A | Applicable | All icons provide meaningful `aria-hidden="true"` when decorative or `aria-label` when interactive. Built-in close button has `aria-label="Close dialog"`. Images require `imageAlt`. | Provide meaningful `imageAlt` when using `imageUrl`. | Axe-core + manual inspect | Verified |
| **1.3.1** | Info and Relationships | A | Applicable | Dialog uses `role="dialog"` or `role="alertdialog"`; `aria-labelledby` points to title; `aria-describedby` points to content; inputs have associated `<label>` or `aria-label`. | Provide clear descriptive title/label text. | Axe-core + DOM check | Verified |
| **1.3.2** | Meaningful Sequence | A | Applicable | Visual order matches DOM reading and tab sequence: Title -> Content -> Input -> Error -> Actions. | Ensure custom HTML DOM maintains logical sequence. | Keyboard tab testing | Verified |
| **1.4.1** | Use of Color | A | Applicable | Status icons (check, X, exclamation) and text accompany all color-coded states (success, error, warning). | Do not rely solely on color in custom messages. | Visual audit | Verified |
| **1.4.3** | Contrast (Minimum) | AA | Applicable | All text and UI control borders meet minimum 4.5:1 contrast ratio against default, dark, and high-contrast theme backgrounds. | If overriding theme colors via custom CSS, maintain contrast. | Color contrast analyser / Axe-core | Verified |
| **1.4.11** | Non-text Contrast | AA | Applicable | Button boundaries and focus rings have >= 3:1 contrast against adjacent backgrounds. | Maintain contrast on custom buttons. | Axe-core | Verified |
| **1.4.12** | Text Spacing | AA | Applicable | Component layouts tolerate expanded letter-spacing, line-height, and paragraph-spacing without clipping or overflowing. | Ensure parent container doesn't have restrictive overflow. | Visual test with text spacing bookmarklet | Verified |
| **2.1.1** | Keyboard | A | Applicable | All functionality accessible via keyboard (Tab, Shift+Tab, Enter, Space, Escape, Arrows in radio/select). | Do not disable keyboard events in host app. | Automated + Manual keyboard test | Verified |
| **2.1.2** | No Keyboard Trap | A | Applicable | Focus is trapped inside modal dialog while open, and releases upon close. Escape key dismisses when `allowEscapeKey: true`. | Ensure host application does not trap focus outside. | Automated tab cycling test | Verified |
| **2.2.1** | Timing Adjustable | A | Applicable | Informational toasts and dialogs with `timer` provide methods to pause, resume, toggle, or increase timer (`stopTimer`, `resumeTimer`, `increaseTimer`). Actionable prompts default to persistent. | Set sufficient timer durations for user reading speeds. | Timer API unit/browser tests | Verified |
| **2.2.2** | Pause, Stop, Hide | A | Applicable | Auto-advancing animations respect user pauses and reduced motion. | Avoid auto-advancing custom carousels. | Reduced motion tests | Verified |
| **2.3.1** | Three Flashes or Below | A | Applicable | No flashing or strobe animations. Icon check/error animations are smooth and non-flickering. | Do not introduce flashing media. | Inspection | Verified |
| **2.4.3** | Focus Order | A | Applicable | Opening modal moves focus to initial target (`focusConfirm`, `focusCancel`, or first input); Tab moves sequentially; closing restores focus to trigger. | Avoid removing trigger elements during modal operation. | Browser E2E focus tests | Verified |
| **2.4.7** | Focus Visible | AA | Applicable | 2px solid high-contrast outline with 2px offset on all focused interactive elements (`:focus-visible`). | Do not reset `outline: none` without replacement. | Visual & keyboard tests | Verified |
| **2.5.3** | Label in Name | A | Applicable | Button text (`confirmButtonText`, `cancelButtonText`) matches its accessible name and `aria-label`. | Match custom button labels with accessible names. | Axe-core inspection | Verified |
| **2.5.8** | Target Size (Minimum) | AA | Applicable | Interactive buttons and controls meet minimum 24x24 CSS px (default buttons are >= 44px height for touch usability). | Provide adequate tap targets for custom controls. | Computed dimension check | Verified |
| **3.2.1** | On Focus | A | Applicable | Focusing inputs or buttons does not trigger unintended form submissions or popups. | Keep event handlers predictable. | Keyboard testing | Verified |
| **3.3.1** | Error Identification | A | Applicable | Validation errors are identified with text and announced via live region, with input linked via `aria-invalid="true"` and `aria-errormessage`. | Provide informative validation error strings. | Screen reader & Axe checks | Verified |
| **4.1.2** | Name, Role, Value | A | Applicable | All controls have valid roles, accessible names, and reflect states (`disabled`, `aria-busy`, `aria-checked`, `aria-invalid`). | Use valid HTML in custom elements. | Axe-core + ARIA audit | Verified |
| **4.1.3** | Status Messages | AA | Applicable | Validation messages and toast notifications announce dynamically without shifting focus via `aria-live="polite"`. | Avoid flooding live regions. | Live region test fixture | Verified |
